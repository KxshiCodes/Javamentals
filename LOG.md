# Learning Log

A simple record of my progress, discoveries, and growth as a Java software developer.

## 5 October 2026

### What I've learned

- **Java fundamentals:** I can create a Java class, write a `main()` method, and print output to the console.
- **Types and variables:** I understand the difference between primitive types and reference types. I also learned about implicit casting, such as assigning an `int` to a `double`.
- **User input:** I can use `Scanner` to read text, integers, and decimal numbers, then store and process the input.
- **Operators and conditions:** I can use arithmetic, comparison, and logical operators to perform calculations and make decisions. I understand how `if`, `else if`, `else`, and `switch` control program flow.
- **Strings:** I learned to compare strings using `.equals()` and use methods such as `.length()`, `.indexOf()`, `.replace()`, `.toLowerCase()`, and `.trim()`.
- **Loops:** I can use `for`, `for-each`, and `while` loops, including `break` and `continue`. I understand that regular `for` loops give me control over an index, while for-each loops are useful when processing every element.
- **Calculations:** I practised calculating sums, averages, factorials, and square roots. I also learned to use `%` to find remainders and identify even and odd numbers.
- **Problem-solving:** Breaking a problem into smaller parts and testing each part as I go makes it easier to understand what I'm building.

### What I'm figuring out

- **Object-oriented programming:** I'm still developing a clear understanding of classes, objects, and instances. A class defines a type, while an object is a particular instance of that class.
- **Problem-solving discipline:** I've noticed that I sometimes rush when I feel close to a solution. I make mistakes with operators, expressions, and calculations, then try different fixes without fully understanding why the previous code failed.
- **Loop boundaries:** I'm continuing to practise how loops start, stop, and update their counters.
- **Edge cases:** I want to get better at handling invalid input, empty data, and unexpected results.

### What's next

- Practise methods and learn how to break programs into smaller, reusable parts.
- Strengthen my understanding of classes, objects, and object-oriented programming.
- Continue building small programs, focusing on readable code, testing, and solving problems independently.
- Slow down when debugging: read the expression, trace the logic, identify the actual problem, and test one change at a time.
